# Integration: S3-Compatible Storage

## Providers
AWS S3 and custom endpoints such as MinIO, R2, Wasabi, or B2 can be used through the AWS SDK S3 client.

## Config
`S3StorageConfig` stores bucket, region, endpoint, `forcePathStyle`, prefix, optional quota, and encrypted access credentials.

## Core Files

- `backend/src/modules/s3/s3.service.ts`
- `backend/src/modules/connected-accounts/connected-account.routes.ts`
- `backend/src/modules/sync/sync-s3.ts`
- upload/file/folder modules for provider-specific branches.

## Filesystem Mapping
S3 has no real folders. Object prefixes/keys must remain consistent with logical folder materialization and reconciliation.

## Optional Direct Uploads

`S3_DIRECT_UPLOAD_ENABLED=false` is the default. When enabled, dashboard
uploads that placement routes to an S3 account may transfer file parts from the
browser directly to short-lived presigned `UploadPart` URLs instead of
streaming them through the backend. The server keeps full authority: it opens
the multipart upload, fixes the object key, advertises the fixed
`S3_DIRECT_UPLOAD_PART_SIZE_BYTES` layout (5 MiB minimum for every non-final
part), authorizes and bounds every part signature, validates the reported ETag
and per-part sizes on completion, performs `CompleteMultipartUpload` and a
verifying `HEAD`, and only then registers the active `File` row. Access and
secret keys never leave the backend, and part URLs are single-object,
single-part, and expiring.

- `S3_DIRECT_UPLOAD_SESSION_TTL_SECONDS` (default 900, 300–3600) bounds the
  whole session; abandoned sessions are aborted remotely and marked failed by a
  background sweeper, and never produce active files.
- `S3_DIRECT_UPLOAD_PART_URL_TTL_SECONDS` (default 300, 30–900) bounds one
  presigned part PUT.
- Disable the flag (no migration needed) to return every provider to the
  server-relayed resumable upload.

`/uploads/direct-s3/*` requires normal bearer auth. CORS on the bucket must
allow `PUT` and expose the `ETag` header for browser completion reporting.

## Optional Direct Downloads

`S3_DIRECT_DOWNLOAD_ENABLED=false` is the default. When explicitly enabled,
an authenticated ordinary attachment download for an active S3 file may receive
a short-lived, single-object presigned GET redirect. 9Drive authorizes and
loads the active logical file before signing; storage credentials and any
long-lived access URL never reach the client.

`S3_DIRECT_DOWNLOAD_TTL_SECONDS` defaults to 300 seconds and is constrained to
30–900 seconds. The signer uses the existing S3 client configuration, including
custom endpoint and path-style settings. A signing failure, disabled flag,
range request, preview, archive, or WebDAV request stays on the backend proxy
path. Configure the bucket’s client CORS policy separately when browser access
is required.
